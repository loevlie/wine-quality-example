STEP 1 / 4

Generate the project

One command scaffolds the lab. Nothing here is hand-written yet.

the command

One command, one question set

Copier asks ~8 prompts (name, Python, PyTorch or JAX, tracker…) and writes a working project. --trust lets it run git init + uv sync for you.

what you get

It arrives ready to run

Dependencies locked, git initialized, pre-commit hooks installed. The printed commands are the whole quickstart.

the map

Five files are yours

Configs, data, model, presets, loss — green files are the ones you'll ever edit. copier update never overwrites them.

the machinery

The rest is template-owned

The training loop, eval, checkpointing, resume — purple files update themselves when the template improves.

known-good baseline

It trains before you touch anything

Not to test the model — to test everything else: the install, the wheels for your hardware, config→CLI, the loop, checkpointing. Synthetic data adds zero unknowns. So when your data breaks something in step 2, the suspect list is exactly the files you edited.

Now the real work — and it's two files.

STEP 2 / 4

Wire in the data

The entry points never change. You describe the data, then load it.

configs.py

Describe the dataset, typed

Six fields say everything train.py needs to know. Pydantic validates them; typos in a flag die before training starts.

configs.py

A field is a flag is a record

Because csv_path is a config field, it's automatically a CLI flag (data.csv_path=…) and it lands in every run's provenance snapshot.

configs.py

The model sizes itself to the data

ModelConfig leaves n_features/n_classes as None — they're filled from DataConfig…

configs.py

…by one visible function

resolved() is the entire "config interpolation system". No ${...} syntax to learn — it's Python you can put a breakpoint in.

datamodule.py

Download once, cache forever

First run fetches 84 KB from UCI and saves it to cfg.csv_path. Every later run — and every test — hits the local file.

datamodule.py

Four lines of real preprocessing

Load, standardize each feature, shift labels 3–8 → 0–5. That's the whole ETL for this dataset — kept where you can see it.

datamodule.py

The seam

create_dataloaders(cfg, seed) is all train.py and eval.py ever call. Swap the dataset class inside it and the rest of the system doesn't notice.

That was the diff. Everything after this is just running things.

STEP 3 / 4

Train & evaluate

Every line of console output is load-bearing. Read it once, trust it forever.

the run

Overrides are just key=value

No YAML edit needed for a one-off: any config field is addressable from the CLI, Hydra-style.

provenance

The line that saves future-you

config.yaml stores the resolved config, the git SHA, and the exact command. Re-running this result in six months is a copy-paste.

training

Real learning, real fast

55% accuracy after one epoch on a laptop CPU. Early stopping (patience) decides when 30 epochs is too many.

the footer

Checkpoints + a command to paste

best.ckpt and last.ckpt are written every epoch; the evaluate line is ready to run as-is.

eval

Eval restores the run's settings

It reads the snapshot next to the checkpoint — data path, model size, loss — so the numbers match training exactly: 0.9350 / 0.6489.

experiments.py

Name the winning settings

The keeper settings become experiment=wine — a preset in version control. Results trace to a commit, not a shell history.

One seed is an anecdote. Five seeds is a claim.

STEP 4 / 4

Prove it

The publication-grade number: a mean, an interval, and nothing hidden.

multi-seed

Same script, five seeds

run_seeds.sh just loops train.py seed=… into one results directory. On SLURM the same thing is a job array.

aggregate

Mean, spread, interval

The aggregator reads each seed's metrics.json and bootstraps a 95% CI — 10,000 resamples of the 5-seed mean.

what the CI shows

Seeds scatter. The interval owns it.

Seed 42 alone would have reported 0.677 — flattering and wrong. The band is the honest range for the mean.

the paper line

0.621 ± 0.038 (5 seeds)

That's what goes in the table. Beating a baseline? Run it with the same seeds and pass --baseline for a paired test + effect size.

That's the whole loop.

Data → train → eval → claim, with provenance at every step. The hands-on tour continues from here: sweeps, Optuna, crash recovery, and a real paired significance test.
